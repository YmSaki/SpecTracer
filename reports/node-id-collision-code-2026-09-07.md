# 上流文書ノード id 衝突の診断コード — DS-536 / DS-897 の矛盾の解消

日付: 2026-09-07 / 対象: `docs/canonical/specification.json` / 起点: 実装 PR #26 が止まった論点

## 1. 争点

上流文書ノードの `id` が 2 箇所（同一ファイル内、またはファイルをまたいで）に現れたとき、scan 層が出す診断コードが正典内で矛盾していた。

- `DS-053`「IDの一意性はスキャン時に全数検査する。」— DOC / VO / TEST の ID を対象とする節（`DS-048`〜`DS-057`）にあり、文書ノードを含む。
- `DS-054`「ID衝突は `chain_integrity` の非 `PASS`（`MISMATCH`）とする（§5.1、§23）。」— 帰結は定めるが診断コードを与えない。
- `DS-536`「E-SCAN-002はerrorであり、Test ID重複（identity collision）を意味する。」— E-SCAN-002 を Test ID に限定。
- `DS-897`（§16.2）「ID衝突はE-SCAN-002として検出する。」— 種別を問わず E-SCAN-002 を割り当て。

`DS-536` と `DS-897` は同層（detailed_spec）で両立しない。実装は現在、文書ノード id の衝突に診断を出しておらず、`DS-053` の義務を満たしていない。

## 2. 上流の逐語

同層の矛盾は上位層で決める。`require` / `spec` 層で「一意 / 重複 / 衝突 / E-SCAN-002」に触れる全ノードを走査した結果、関係するのは次の 2 件である。

- `SPEC-197`（spec）「マージ後の論理的不整合（ID衝突、dangling reference、承認の失効）はスキャンと整合性検査で検出する（§23）。」
  → **ID 衝突一般**の検出を義務づける。**コードは割り当てていない。**
- `SPEC-377`（spec）「`vtest doctor` は、同じTest IDの重複（E-SCAN-002）、covers先VOの欠落（E-SCAN-003）、文書鎖のリンク切れ（E-SCAN-012）、`root` 層のノードを除き実効的な上流（自分の辺 ∪ 先祖の辺）を持たない孤児ノード（E-SCAN-016）、承認・判断・Evidenceのハッシュ束縛による失効（診断 `STALE`）など、version control の構文的整合性だけでは判定できない論理的不整合を検出する。」
  → **E-SCAN-002 を「同じ Test ID の重複」に束縛している。**

Test ID の一意性そのものの上流は `REQ-055` / `REQ-097` / `REQ-199`〜`REQ-202` / `REQ-274` / `SPEC-276` / `SPEC-353`、恒久 SRC ID は `REQ-155` / `REQ-156`。いずれも文書ノードの id には触れない。上流に**文書ノード id 衝突専用のコード割り当ては存在しない**。

## 3. 判定

**上流は「ID 衝突全般 = E-SCAN-002」とは言っていない。** `SPEC-377` は E-SCAN-002 を Test ID の重複に束縛しており、`SPEC-197` は ID 衝突一般の検出を義務づけるがコードを与えない。したがって:

- `DS-536` の限定は**上流どおり**であり、狭窄ではない。
- `DS-897` の一般化は**上流に根拠が無い**。これが矛盾の側である。

文書ノード id 衝突に割り当てるコードは、上流が沈黙しているため下位で決める必要がある。**新設はしない。** `E-SCAN-010` を用いる。判別は F7 の基準（受け取った者の行動が変わるか＝直す場所が違うか）による。

| ID の種別 | 直す場所 | コード | 同層の根拠 |
|---|---|---|---|
| Test ID | adapter が発見した source | `E-SCAN-002` | `DS-536`・`SPEC-377` |
| `.verify/` レコードの id（上流文書ノードを含む） | 当該レコードファイル | `E-SCAN-010` | `DS-428`・`DS-1294`・`DS-1658` |
| 恒久 SRC ID | 宣言した Source Target | `E-SCAN-011` | `DS-545`・`REQ-155` |

E-SCAN-010 を選ぶ根拠は 3 点。

1. 同コードは既に `.verify/` レコードの同一性欠陥の一般コードである。`DS-428`「prefixed / bareの混在、ファイル名と `id` のpayload不一致、または同じpayloadの複数recordはE-SCAN-010とし、いずれかを選ばない。」が「同じ id のレコードが 2 件 → 候補を選ばない」という、本件と同型の扱いを既に定めている。
2. 上流文書は `.verify/doc/` のレコードとして保存される（`ROOT-047`・`DES-586`）。行動（当該レコードファイルを直す）が既存の E-SCAN-010 と一致する。
3. `DS-1658` が同じ判断を既に下している。文書ファイルの層配列と id 接頭辞の不一致について「違反は宣言された schema との不一致であり、状態は …（E-SCAN-010）による。**新しい診断コードは作らない。**」

**この割り当ては REWORD ではなく規範変更である。** 前身 `DS-1645` の逐語「互換正規化後のlogical record ID重複」は文書ノードを含まない（ノードは互換正規化を通らず、`DES-585` により文書ファイル自身は id を持たない）。したがって退役台帳を経由した新 id で適用した。

## 4. 適用

| 種別 | 旧 id | 新 id | 内容 |
|---|---|---|---|
| 規範変更（退役） | `DS-897` | `DS-1675` | §16.2 の衝突検出を種別ごとの割り当てへ。`derives_from: [SPEC-197, SPEC-377]` |
| 規範変更（退役） | `DS-1645` | `DS-1676` | E-SCAN-010 の符号表行に「上流文書ノードの `id` が 2 箇所以上に現れること（同一ファイル内・ファイル間を問わない）」を追加。`derives_from: [SPEC-197]` |
| 新規 | — | `DS-1677` | 規則本体。§3.2（`DS-054` の直後）。衝突時は `E-SCAN-010` を報告し、当該 id を参照する `derives_from` は**いずれの候補も選ばず**、当該ノードと参照元ノードの `chain_integrity` を `MISMATCH` とする。`derives_from: [SPEC-197]` |
| 辺の追加 | `DS-053` | — | `derives_from` に `SPEC-197` を追加。文は DOC / VO / TEST を対象とするのに、辺が Test ID と SRC ID（`REQ-055` / `REQ-155` / `REQ-156`）しか指していなかった。文は変えていない。 |
| 散文の指し先 | `DS-1658` / `DES-586` | — | 退役した `DS-1645` への参照を `DS-1676` へ付け替え。description のみ。 |

退役 2 件は `docs/canonical/relations/retired-ids.json` に記録した（`reason: node id collision diagnostic 2026-09-07`）。

**4 検査・5 状態は変えていない。** 診断コードの新設も無い。帰結は既存の `DS-054`（ID 衝突は `chain_integrity` の非 `PASS`）に閉じている。

## 5. 目的（Issue #11 F1）との対応

同じ `id` を持つ 2 ノードが存在すると、そこへ張られた `derives_from` がどちらへ解決されたか確定しない。上流に根拠が無い規範が根拠を持つように見え、**偽のリンクが `chain_integrity` を通る**。`DS-1677` は候補を 1 件も選ばないことで、この経路を fail-closed に閉じる（`DS-428`・`DS-564` と同型）。
