# VO トレーサビリティ・チェーン（フォーマット・サンプル v4）

ルートは要求そのもの。上から下へ読めば、その検証項目が「なぜ要るのか」を要求から辿れる。ID は各ノードの見出しに `種別（ID）— 意味` の形でインライン（1行）。

**構造（詳細仕様の項目ごとに枝分かれ）**:

```
詳細仕様項目
├─ 実装         ← この項目を実現する本体コード
└─ VO           ← この項目を検証する義務
   └─ テスト     ← 何を入力したら何が返る必要があるか
      └─ テスト実装 ← 実際のテストコード
```

実装 と VO(→テスト→テスト実装) を兄弟に置くので、実装あり+テスト実装なし＝「作ったが未検証」、実装なし+テスト実装あり＝「仕様とテストはあるが未実装」が見える。**この文書は最終的にデータ（ノード + リンク）から自動生成する**（SpecTracer 自身のトレース機能の先取り）。新モデルの実装・テスト実装は #13 スコープ外なので、多くの項目で「未」——それがこの木で可視化される。

## 要求（R-1・一次場面）— AI の完了報告を信じて、嘘の PASS のままマージする事故を防ぎたい

- **要件（要件定義 §4.4／§8）** — テストが検証対象の結果を実際に確かめているか（合否を判定する装置を持っているか）を検査できること。
  - **基本仕様（基本仕様 §5.4）** — 「照合装置の存在（oracle_presence）」を4検査の1つとして持つ。照合の仕掛けが無いテストはランナーが緑でも FAIL、機械で断定できなければ UNKNOWN。
    - **詳細仕様（詳細設計 §7.1／§7.2）** — テストコードを静的解析し、次の各構造を検出する。項目ごとに実装と VO が並ぶ。

      - **項目: アサーションが1つも無い**
        - **実装** — アサーション不在を検出する解析。`crates/vtest-audit/`（現状: 旧モデル・未追随）
        - **VO（VO-ORACLE-01）** — アサーションを1つも持たないテストを FAIL と判定できること。
          - **テスト** — 入力: 本体にアサーションが無いテスト。oracle_presence が **FAIL** を返す必要がある（それ以外なら失敗）。
            - **テスト実装** — 現状: 未（#13 スコープ外）

      - **項目: 定数だけを比較している（例 `assert!(true)`）**
        - **実装** — 定数比較を検出する解析。`crates/vtest-audit/`（現状: 旧モデル）
        - **VO（VO-ORACLE-02）** — 定数だけを比較するテストを FAIL と判定できること。
          - **テスト** — 入力: `assert!(true)` だけのテスト。oracle_presence が **FAIL** を返す必要がある（それ以外なら失敗）。
            - **テスト実装** — 現状: 未（#13 スコープ外）

      - **項目: 自分自身を比較している（例 `assert_eq!(result, result)`）**
        - **実装** — 自己比較を検出する解析。`crates/vtest-audit/`（現状: 旧モデル）
        - **VO（VO-ORACLE-03）** — 自己比較のテストを FAIL と判定できること。
          - **テスト** — 入力: `assert_eq!(result, result)` のテスト。oracle_presence が **FAIL** を返す必要がある（それ以外なら失敗）。
            - **テスト実装** — 現状: 未（#13 スコープ外）

      - **項目: 対象を呼ぶだけで結果を検証していない**
        - **実装** — 「呼ぶが結果を判定に使わない」構造を検出する解析。`crates/vtest-audit/`（現状: 旧モデル）
        - **VO（VO-ORACLE-04）** — 対象を呼び出すが結果を判定に使っていないテストを FAIL と判定できること。
          - **テスト** — 入力: 対象を呼んだ後に結果を見ず `assert!(true)` するテスト。oracle_presence が **FAIL** を返す必要がある（それ以外なら失敗）。
            - **テスト実装** — 現状: 未（#13 スコープ外）

      - **項目: マクロ展開の中など、機械が構造を追いきれない**
        - **実装** — 解析視界を超える箇所を UNKNOWN として扱う分岐。`crates/vtest-audit/`（現状: 旧モデル）
        - **VO（VO-ORACLE-05）** — 照合の有無を静的に断定できないテストを UNKNOWN と判定できること。
          - **テスト** — 入力: 照合がマクロ展開の内側にあり静的に追えないテスト。oracle_presence が **UNKNOWN** を返す必要がある（FAIL でも PASS でも失敗）。
            - **テスト実装** — 現状: 未（#13 スコープ外）
