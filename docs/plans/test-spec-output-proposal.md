# テスト仕様書の出力 — 要件追加案（承認待ち）

状態: **提案**。正本（`docs/canonical/specification.json`）は変更していない。承認後に、正本の変更を独立した PR で行う（計画 v0.2 §0.3、P-005）。実装はその PR が merge されてから始める。

## 1. 位置付け

このツールは、テストコードに `@` 注釈を埋め込み、Doxygen のようにテスト仕様書を出力する機能から始まった。のちに、実装ソースと上流仕様へのトレースを加えた。

現在の正本には、後半の「トレース」を支える要件だけがある。最初の「テスト仕様書の出力」に当たる要件はない。最も近い NFR-008（人間が VO・Test の不足、不一致、NG 理由を一覧で理解可能であること）は、検証結果の出力であり、仕様書の出力ではない。

CLI も同じ状態になっている。`main`（v0.1.0-alpha.1）にあった `test list/show` と `report` は、`develop` の CLI にない。ただし別紙A §12.2 には `vtest test show/list/query` が残っている。仕様と実装が食い違っている。

## 2. 出力するもの

1 つの Test を 1 つの項目にして、次を出す。値はすべて `scan` が adapter から受け取る `TestEntity` から取る。新しい入力は増やさない。

| 項目 | 取得元 |
|---|---|
| Test ID | `id` |
| 目的 | `intent` |
| 検証する VO とその主張 | `covers` → VO の `claim` |
| 対象（Source Target） | `targets` |
| 入力・期待・種別・ケース・関連 Test | `input` / `expect` / `kind` / `cases` / `related` |
| 所在 | `location`（adapter・path・locator） |

次の整理もつける。

- VO ごと、path ごとの目次
- 注釈がなく、管理されていない Test の一覧（`ManagedTestLink::Missing`）
- 解決できなかった `covers` / `target` の一覧

## 3. 守る性質

1. **言語に依存しない。** `TestEntity` は adapter が返す共通の形なので、Rust と synthetic adapter の Test は同じ形式で出る。
2. **欠落を黙って落とさない。** 注釈のない Test、不完全な Test、解決できない参照は、一覧に必ず出す。
3. **仕様書は検証結果ではない。** 仕様書に `PASS` を書かない。検証状態を併記する場合は、`verify` の値をそのまま写し、状態を新しく作らない。
4. **決定論的に出す。** 同じ入力なら同じ出力になる。順序は adapter ID・path・Test ID で決める。
5. **CLI と MCP は同じ JSON の形を返す。** Markdown は JSON から作る派生物であり、正本ではない。

## 4. 要件文案（要件定義 §22 インターフェースへの追加）

> 本システムは、管理対象 Test の宣言（目的、検証する VO、対象、入力、期待、種別）から、人が読むテスト仕様書を出力できる。
>
> テスト仕様書は、宣言されていない Test、宣言が不完全な Test、解決できない参照を省略せず、一覧に含める。
>
> テスト仕様書の出力は adapter に依存せず、同じ入力から同じ内容を出力する。
>
> テスト仕様書は検証状態の代替ではなく、出力そのものが `PASS` を意味しない。

## 5. 受入条件の案

- Rust と synthetic の混在プロジェクトで、両方の Test が同じ形式で出る（既存の混在 fixture を再利用できる）。
- 注釈のない `#[test]` が、「未管理」として出る。
- 解決できない `covers` が、省略されずに出る。
- 並べ替えた入力でも同一の出力になる。
- CLI と MCP が同じ JSON を返す。
