# VO 不足候補リスト（Owner 裁定用・1枚）

本書は、複数のレビュー観点（レンズ）が別々に挙げた「検証義務（VO）の抜け・弱さ」の候補を、意味が同じものを 1 件に畳んだうえで、Owner が行ごとに裁定できるよう 1 枚にまとめたものです。各行は単独で読める完結文で書き、実装者向けの圧縮記法は本文に出しません。ここに書いた「私の提案」は提案であって決定ではありません。

## 凡例（4 分類の意味）

- **未カバー**: その検査系統（chain_integrity など）自体は存在するが、この特定の経路・状態値を実際に行使する VO が 1 本も無い。検査の穴。
- **弱い**: 関連 VO が意味文で触れている、または隣接ケースを行使しているが、この義務の核心を確かめていない。検査の甘さ。
- **過剰 VO**: 既存 VO が凍結仕様と食い違う、または過剰に規定している。追加ではなく、既存 VO の修正または削除が要る。
- **抽出漏れ疑い**: 上流要求（R-／P-／NFR-）の末端義務が、対応する検査系統ごと宣言鎖に見当たらない。個別テストの穴ではなく、能力・機能レベルの欠落。

各行の「現状」欄には、既存 VO が実際に何を行使しているか（何を行使していないか）を書きます。分類が元レンズの申告と異なる場合は、元の申告状態も併記します。

用語の下敷き（初出時に平易化）:

- **E-SCAN-002**: テスト識別子（Test ID）の衝突。
- **E-SCAN-004**: 宣言された検証対象が実在しない（対象不在）。
- **E-SCAN-009**: 関係リンクの端点が不在。
- **E-SCAN-010**: 関係識別子の正規化形の衝突（bare ULID と `REL-` 接頭辞付きの重複・混在、ファイル名と record ID の不一致）。
- **E-SCAN-011**: 宣言対象が複数候補へ曖昧化した状態。
- **ManagedTestLink::Multiple**: 発見された 1 つのテスト（1 つの実行 construct）に、対応する管理宣言が 2 件以上ある状態。
- **MISMATCH**: 宣言側（上流）を先に直すべき不一致。是正方向は「上流修正」。
- **NO_EVIDENCE（診断 NOT_EXECUTED / NOT_CHECKED）**: 証拠が無い／未検査の状態。是正方向は「証拠作成」または「検査の実施」。MISMATCH とは是正方向が正反対。
- **oracle_presence（照合装置検査）／target_binding（検証対象実現検査）／chain_integrity（宣言鎖検査）／orphan_detection（孤立検出検査）**: v0.1 の 4 検査。

## Owner に裁定してほしいこと

各行について、次の 4 つのいずれかを 1 行あたり 1 つ選んでください。**埋める**（新しい VO を追加する）／**統合**（既存の名前付き VO を強化してこの義務を確かめさせる）／**対象外**（この義務は VO 化しない。理由を添えて）／**削除**（過剰 VO の場合、既存 VO を修正または削除する）。「私の提案」欄は私の推奨であり、最終判断は Owner にあります。1 行に動詞が 2 つ入らないよう、判断が分かれる箇所は行を分けてあります。

## 付録: 特に高 severity の未カバー（再掲）

Owner が最初に見るべき、severity 高で検査の穴（未カバー）となっている行:

- **U1** — ManagedTestLink::Multiple（1 テストに管理宣言が複数）を宣言鎖検査の MISMATCH と判定する VO が無い。VO-CHAIN-TEST-04 は Test ID 衝突側だけを行使。嘘の合格でのマージ（R-1）を素通しする経路。
- **U2** — 照合ヘルパ等の依存要素が正当性未確認・信頼基盤未識別のまま照合装置検査を成立側にしない終端条件（§8.2 条項2）の VO が無い。正当性未確認のヘルパで assert するテストが緑になりうる。
- **U3** — 複数宣言対象での DA-003 対象別畳み込み・1 対 1 対応を照合装置検査側で確かめる VO が無い。一部対象の結果未検証が合格へ漏れる false-PASS 経路。

参考として、未カバー以外にも高 severity が残っています: 抽出漏れ疑い **G1**（VO 分解・展開能力）・**G2**（並列保存不変条件）、弱い **W1**（瑕疵なし入力の真陽性 PASS）。これらも同格に扱う判断があり得ます。
