# 層の定義と仕分け規則（2026-09-05、Owner 定義）

Owner の定義（逐語）:

> 基本仕様 = 何を実現するかを確定する
> 基本設計 = それをどんな構造で実現するかを決める
> 詳細設計 = 各部品をどう実装するかまで落とす
> 詳細設計は自然言語で記述したコードになるのは避けたい。

PM の言い換え（Owner 確認済み）: 詳細設計 = 各部品が何を持ち、何を受け取り、何を返し、どの順で確定するかを、実装が迷わない粒度まで落とす（型とデータの流れ）。

## 1. 層（5段）

| 層 | 配列名 | id | 問い |
|---|---|---|---|
| 要求 | `request` | `R-N` | 誰が何を欲しているか |
| 要件定義 | `require` | `REQ-` / `P-00N` | 満たされたとはどういう状態か（WHY） |
| 基本仕様 | `spec` | `SPEC-` | 何を実現するか。外から確かめられる約束 |
| 基本設計 | `basic_design` | `BD-`（area `BDA-`） | どんな構造で実現するか。部品の分け方、部品同士の境界、外から見える形 |
| 詳細設計 | `design` | `DES-`（area `DA-`） | 各部品の型とデータの流れ。実装が迷わない粒度 |

辺（`derived_from`）は層をまたぐ参照だけ。5段になっても辺の種類は増えない。

## 2. 仕分けの判定（1文ずつ）

順に当てる。最初に当たった層に置く。

1. **約束か決定か。** 実装者が別の作り方を選んでも真のままなら約束 → `spec`。別の作り方で嘘になるなら決定 → 2 へ。
2. **外から見える決定か、内側の決定か。** 利用者・他システム・adapter 作者から見える形（入口の種類、ディレクトリ構成、レコードの種類、adapter と core の責務分界、コマンドと引数、診断コードの体系）→ `basic_design`。内側（型のフィールド、DTO、判定の段と各段の入出力、状態遷移の条件）→ `design`。
3. **コードか。** 手順の順序、ループ、分岐の実装順、言語固有の書き方を述べていて、別の書き方をした瞬間に嘘になる文 → `design` に置いたうえで `code_like: true` を付ける（削除候補。仕分けでは消さない）。

**PM の仮置き（提案。Owner の定義から私が導いたもので、Owner の裁定ではない。試験仕分けの結果と一緒に出し、違うものは止めてもらう）**:
- 「検証状態は5つのみ」→ 約束 → spec。
- 「インターフェースは CLI と MCP の2入口」→ 外から見える決定 → basic_design。
- 「`.verify/doc/<id>.yaml` に1レコード1ファイル」→ 外から見える決定（利用者が触る）→ basic_design。
- 「`SourceLocation` は `adapter, path, locator, byte_range` を持つ」→ 型 → design。
- 「`E-SCAN-016` は orphan_detection = MISMATCH を表す」→ 外から見える体系 → basic_design。
- 「`rust-cargo` adapter は第6段で Source Target を抽出する」→ 段の入出力なら design、段の中の手順なら code_like。
- 別紙C の受入条件は、約束を検証可能な形で書き直したもの → spec に置く。ただし fixture の中身の定義は basic_design。

**未解決の緊張**: 昨日の Owner 案「基本仕様＝システム概要・システム構成・機能一覧表」と、今日の判定1「別の作り方でも真なら約束 → spec」は、同じ結果にならない可能性がある。判定1のままだと状態表・Evidence 有効条件・ハッシュ束縛のような振る舞いの契約はすべて spec に残る。試験仕分けの数で確かめる。

## 3. 仕分けの出力

`docs/canonical/relayer/<fragment>.json`: `{ "<現在の id>": { "layer": "spec|basic_design|design", "reason": "<1行>", "confidence": "high|low", "code_like": false } }`。
`confidence: low` の文は Owner に一覧で出す。仕分けは文を書き換えない。

## 4. 仕分け後

`build.py relayer apply` で fragments に `layer` を書き、再ビルド。id は接頭辞が変わるので付け直し（固定は分割後）。辺は `cites`・導出表・トレーサビリティ表から再計算する。
