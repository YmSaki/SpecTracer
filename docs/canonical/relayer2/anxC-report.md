## 5. 適用した機械的な内訳ルール（詳細仕様内の list_item 選択、再現用）

330件が最終的に `detailed_spec` に置かれた。層は全て同じでも、一覧は詳細仕様だけで「すべての入力条件 / 入力値の範囲・形式・制約 / すべての出力結果 / 正常系・異常系・境界値・状態ごとの振る舞い / 状態遷移条件 / 例外条件 / 競合する条件の優先順位 / エラーの外部的意味 / 仕様上の不変条件 / 受入条件・検証可能な期待結果」の10項目を持つため、文ごとに1項目を選んだ。優先順位（先に当たったものを採用）:

1. 優先順位・採用規則の明示 → 競合する条件の優先順位（4件）
2. 状態遷移の明示（`draft`⇄`approved`等） → 状態遷移条件（4件）
3. 値域・文字列形式の明示（`値域は…`等） → 入力値の範囲・形式・制約（6件、うち個別確認1件を含む）
4. 診断コード（`E-*`/`W-*`）・5状態語彙・4診断ラベル・終了コードのいずれかを含む → 受入条件・検証可能な期待結果（133件）

6. 出力内容の列挙（「〜を記録する。」「〜を返す。」等、条件を伴わない） → すべての出力結果（10件）
7. 残り（診断コード・5状態を明示しない一般的な集約・分類規則） → 正常系・異常系・境界値・状態ごとの振る舞い（122件）
